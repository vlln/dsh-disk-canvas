# dsh-disk-canvas

> 把磁盘扫成一张可批注的提案：Agent 标注、你来决定、删前可预览。（DeepSeek Harness 插件）

你在 Finder / SpaceSniffer 里能看到「哪个文件夹最大」，但看不到「它是什么、删了会怎样」。
这个插件把磁盘变成一张**画布**：每个方块按体积占位、按 Agent 给出的类别聚合，点开有判断和依据；
你的决定（保留 / 待清理 / 待复查）直接标在方块上，汇总成一份可带走的提案。

![磁盘画布：左树图、右检查器](docs/screenshot.jpg)

同一个目录的两种镜头：树图看「哪里大」，列表逐项过——[列表视图](docs/screenshot-list.jpg)
把画布上小到不足 1 像素的项也全列出来，可以勾选后一次处理。

**它不删文件。** 唯一的写操作是「移动」：你点「执行移动」之后，插件才把选中的项移到你指定的目录，
逐项检查、不覆盖、不跨盘。

## 安装

```sh
dsh plugin --profile web add github:vlln/dsh-disk-canvas
```

装完刷新页面。升级：把上面的 `add` 换成 `dsh plugin --profile web update dsh-disk-canvas`。

- **画布入口**：会话页签里的 **磁盘画布**（与「对话」「轨迹」并排）。
- **整理模式**：新建任务时在模式选择器里选 **磁盘整理**——这个 preset 自带提示词与
  `disk_canvas_*` 工具，其它模式看不到这些工具。
- **前置**：macOS + dsh `0.2.1-rc.1` 或兼容的 0.2.x。

## 两种用法

| 用法 | 入口 | 你能做什么 |
|---|---|---|
| 看与批注 | 任意会话 → **磁盘画布** 页签 | 树图、检视器、保留/待清理/待复查、预览、复制清单 |
| 让 Agent 参与 | 新建任务 → 模式选 **磁盘整理** | Agent 用 `disk_canvas_scan` / `state` / `claim` 扫描与标注，你在画布上改 |

页签与工具是分开的：画布在哪种模式都能打开（它只是数据视图），工具只在「磁盘整理」模式下挂载。

## 用起来

| 你做什么 | 画布给你什么 |
|---|---|
| 打开「磁盘画布」页签 | 主目录的第一层，按体积排的树图；方块默认中性，语义由文字承载。标题行右侧是 **facet**：Agent 把这一层归成的几类，点一个只高亮那一类 |
| 点一个方块 | 右侧检查器：这是什么、为什么、依据与把握、体积 / 占比 / 文件数 / 最近改动 |
| **在画布上拖一个框** | 框里的方块一起选中（⇧/⌘ 点方块是逐个加选），底部浮出批量条：几项、多少 GB、含几个个人内容 / 谨慎项 |
| **点批量条上的决定** | 一次给这十几项写同一个决定；比逐个点快一个数量级 |
| **点右上角列表图标** | 换成列表视图：76 项全在，包括画布上小到点不到的 42 项；行首复选框可以多选，表头复选框是全选；窗口窄了自动收起类别/占比列 |
| **点「按规则选」** | 一键选中「安全 / 谨慎 / 个人 / 未知 / 未审 / 已标待清理」整档（只作用于当前这一层），再走批量条 |
| **点右上角第三个图标（跨层索引）** | 扫描时顺带记下的「按名字可清理」的目录：node_modules / Caches / dist·build·target / __pycache__·.venv / Logs / .Trash / DerivedData。按类分组，显示处数与合计，整组勾选后直接批量决定 |
| **双击索引里的一行** | 跳到那一层：扫它的父目录、选中它，并切回树图（检查器里也有「在画布中定位」） |
| 计划条上的「已移走 N 项」 | 跑完清理脚本后回来重扫一次：上一轮标了待清理、这次不在了的项会记一笔（时间 / 条数 / 体积）。它只是台账，不提供恢复——恢复去废纸篓 |
| **在画布上滚轮** | 以指针为锚点放大到 6 倍，文字不跟着变大（放大后更多小方块会显示名字）；`Alt`+拖 或 中键拖 平移，`0` 或右下角百分比复位 |
| 双击目录方块 | 进入该目录（方块放大铺满画布，再淡出成新一层） |
| 标一个决定 | 保留 / 待清理 / 待复查 + 一句备注；方块立刻变样（绿框 ✓ / 红底 ✕ / 黄虚线 ?） |
| 不选任何方块 | 检查器变成总览：审查进度、四档计数、按体积排的待审队列（点一行直接选中） |
| 点「预览清理后」 | 隐藏待清理块，看剩下的结构；**磁盘没有任何改动** |
| **在索引里搜路径** | 输入 `project` / `node_modules`，只留下匹配的目录（分组自动展开，组头数字跟着变成匹配数） |
| **点「在对话里问这一项」** | 把当前方块变成一个具体问题（带路径和现有语义）填进对话框，你按 Enter 就发；不新开界面 |
| **选中后点「移到…」** | 填一个目标目录，这些方块就带上 `→ 目录` 角标（只是登记，不动文件）；计划条出现「待移动 N 项」 |
| **点「整理预览」** | 逐项列出「从哪到哪」和冲突（目标已存在 / 跨盘 / 目标是自己的子目录）；点「执行移动」才真的搬 |
| **点「撤销这批」** | 把刚移走的一批移回原位：先看反向预览（回哪、哪些会被跳过），再点执行 |
| 点「导出」 | 两个产物：**清单**（Markdown，复制进剪贴板，不落文件）、**清理脚本**（`sh`，默认演练） |

备注**边写边存**（600ms 防抖），换方块也会先把没落盘的字写掉。右上角的检查器按钮可以收起，
收起后画布占满整宽——只想想看清楚结构的时候用它。窗口窄到 560px 以下时，检查器自动变成浮层：
不选中任何方块时不占位，选中后浮在画布上，关掉就回到画布。

多选时按空格 / K / D / U 会把决定应用到**所有选中项**；Esc 是「取消选择」，不做返回——
返回交给面包屑和「向上」。

### 键盘

| 键 | 动作 |
|---|---|
| 空格 | 循环标记：无 → 待清理 → 保留 → 待复查 → 无（多选时作用于全部选中项） |
| K / D / U | 直接标：保留 / 待清理 / 待复查 |
| Backspace / 0 | 清掉选中项的决定 |
| ← ↑ ↓ → | 按方位在方块之间移动（列表视图里是上下移动） |
| Enter | 进入选中的目录 |
| Esc | 取消选择 / 取消正在拖的框选 |
| 0 | 缩放复位（100%） |

标记直接画在方块上：保留是绿框 + ✓，待清理是红底红框 + ✕，待复查是黄虚线 + ?。
悬停 220ms 出信息卡；左上角路径的每一段都可以点回去。
颜色按**类别**上色：每类一个固定色号，淡填充 + 左侧 3px 色条。未标注的方块是白色 + 虚线框——
一眼能看出「还没人看过」，而不是「看过了没事」。点一个 facet 时其余类别转灰（不是变透明），
颜色表达的是「我在看哪一类」，不是「哪一类更危险」。色号只从 8 个原色里取，用完了退回中性色：
不为新类型发明新颜色，也不让「橙色=安装包」因为多了一类就重排。

## 配色与 token

界面颜色分三层，组件里不写颜色字面量：

| 层 | 是什么 | 例子 |
|---|---|---|
| 基础 | dsh 的 `--dsw-*` 主题变量 | `--dsw-alias-label-primary`、`--dsw-alias-border-l2` |
| 语义 | 插件自己的 `--dc-*`，定义在 `.dc-root` | `--dc-surface`、`--dc-recess`、`--dc-ink-1/2/3`、`--dc-mark-keep/delete/unsure`、`--dc-hue-0…7` |
| 强度 | 三个数控制整体浓淡 | `--dc-facet-fill:8%`、`--dc-facet-edge:72%`、`--dc-facet-dim:24%` |

两条规矩：**饱和色只给决定**（✓ 保留 / ✕ 待清理 / ? 待复查），类别只用低饱和填充 + 色条；
**色号落在账本里**（`facetHue`），换会话、重启、重扫都不重排。8 个原色用完后退回中性灰。

## 定期扫描：两条路

- **插件内定时器**（齿轮菜单）：关 / 每天 / 每周，宿主进程按间隔重扫上一次的根。简单、不依赖会话，但 dsh 关着就不扫。
- **走 dsh 的定时提醒**：在「磁盘整理」模式下对 Agent 说「每周一扫一次」，它用 `schedule` 工具给当前会话
  定一个提醒；到点后提醒投递回这个会话，Agent 再跑一遍扫描并汇报增量。这种方式会真正启动一次会话，
  适合「想让我每周给你一份报告」而不是「只想让数据新鲜」。

两者不冲突：定时器管数据，提醒管汇报。

## 提案快照：把这份审查带走

齿轮菜单里的「提案快照」：

- **导出**：`disk-canvas-proposal.json` —— 你的决定、Agent 的判断、记住的规则（不含体积明细，很小）
- **导入**：只补本地没有的——已经做过的决定不覆盖、已有的规则不重复，导入后会告诉你
  「导入 N 条决定、M 条判断、K 条规则，跳过 J 条已有决定」

用途是**交接**：换台机器接着审、让同事在你看过的判断上继续、或者把一次审查的结论留档。

## 记住规则 / 自动扫描

右上角的齿轮：

- **自动扫描**：关 / 每天 / 每周。开着的时候宿主进程按间隔重扫上一次的根；
  启动时如果数据比间隔还旧，会补扫一次。**dsh 没开着就不会扫**——这不是常驻守护进程。
- **记忆规则**：在索引里选中一整类，批量条上勾「记住这类」再给决定，以后扫到同类目录自动这样标。
  规则只补「还没有人做过决定」的项，你手动改过的不会被覆盖；撤销规则时，会把它写下且你没改过的决定一起收回。

## 清理脚本：默认只演练

「导出 → 清理脚本」生成一个 `disk-cleanup.sh`：

- **不做 rm**：把待清理项 `mv` 到 `~/.Trash/`（同名时加时间后缀）。插件不再维护自己的隔离目录，
  也不写 manifest——恢复就是废纸篓自己的事
- **默认演练**：直接 `sh disk-cleanup.sh` 只打印会移动什么；加 `--yes` 才真的移动
- 已经不在的路径会跳过并提示；`/` 和 `$HOME` 直接拒绝；路径里的引号会被正确转义
- 脚本里同时包含「当前层」和「索引里的其他层」的待清理项——和你导出的清单是同一批

这是 v0 第一次给出「执行面」，但仍然不碰删除：移动、可逆、默认不动。

跑完脚本回到画布、点一次「重新扫描」：上一轮标了待清理、这次不在了的项会被记进**执行台账**
（时间 / 条数 / 体积，显示在计划条上）。它只回答「我处理过没有、回收了多少」，不提供恢复入口。

## 持久化与历史

扫描快照、你的决定、Agent 的标注都写在 `$DSH_HOME/data/dsh-disk-canvas/ledger.json`：

- 每根目录保留**最近 20 次扫描 / 90 天 / 总量 ≤ 5 MB**（只存顶层聚合，不存整棵树）；
- 重启 dsh 后画布用上次快照**秒开**，不会先重扫；点「重新扫描」才更新；
- **换目录不等于重新测量**：有快照就先显示（标题行标「缓存 · N 分钟前」），超过 10 分钟才在后台刷新，
  刷新期间旧画面继续显示、扫完一次替换。只有「重新扫描」/ 自动扫描 / Agent 主动扫描才写进趋势，
  导航只更新当前画面——所以「近 N 次 +12.6 GB」记的是磁盘的变化，不是你点了哪里；
- 标注按路径全局保留，换目录、换会话、重启都还在；
- `disk_canvas_history` 让 Agent 读历史与增量（"这周哪个目录在涨"）。

扫描是插件的持久周期，会话只是某次审查；关掉会话不影响账本。

## 能力面

**Preset**

| 模式 | 说明 |
|---|---|
| 磁盘整理 | 自带提示词的磁盘审查 Agent：只分析、标注、预览；工具只有 `disk_canvas_*`，没有 shell / 删除能力 |

**Tools**（只挂在「磁盘整理」模式）

| 工具 | 说明 |
|---|---|
| `disk_canvas_scan` | 扫描一个目录（默认主目录）的直接子项，返回体积最大的若干项与规则标注 |
| `disk_canvas_mark` | 直接给一批路径写决定（和用户按 K/D/U 同一份数据）；只补没决定的，可整批撤销 |
| `disk_canvas_object` | 对用户已做的决定写一句异议；不改决定，用户改了决定就失效 |
| `disk_canvas_organize` | 给一批路径登记「移到某目录」（和手动移动同一份数据）；不执行，等用户点确认 |
| `disk_canvas_state` | 读当前画布状态：计划、条目、你的决定 |
| `disk_canvas_claim` | 给某路径写一条语义（一句话 + 类别 + 依据），不执行删除 |
| `disk_canvas_history` | 读账本里的历史扫描与增量（最多 20 条） |

preset 里还有官方只读文件工具：`read` / `read_image`（`dsh-tool-fs` 关掉 write/edit）、
`glob` / `grep`（`dsh-tool-fs-search`）。**没有 shell、没有写/删工具**。

## 安全与数据

- **不删除**：没有任何删除接口。移动只在「执行移动」被点击后发生，且逐项检查冲突（不覆盖、不跨盘）。
- **本地**：扫描在宿主进程内完成，不发网络请求、不上传路径或清单。
- **落盘但只在本地**：扫描快照、决定与标注写在 `$DSH_HOME/data/dsh-disk-canvas/ledger.json`，不上传、不同步。
- **诚实**：没有证据的项标 `unknown`，不会把「不确定」包装成「安全」。
- **同源**：写面（scan / annotate）校验 `Origin` 与 `Host`，并限制请求体大小。

## 已知限制

- macOS 首版；Linux / Windows 未验证。
- 只扫当前一层（双击下钻）。首次扫描边扫边出（100 GB 级主目录约 15–60 秒），单个超大目录可能被条目/时间预算截断并标「部分结果」，不假装扫完。
- 不解析压缩包、虚拟机镜像、快照内部；容器只当普通文件。
- 「永久保留」目前是单次会话内的批注，不是跨会话规则（规则泛化在路线图上）。
- 插件不做语义判断：没有 Agent 时，画布只有体积、时间、文件数这些事实——和 SpaceSniffer 一样。
  「这是什么、能不能删」由 Agent 的语义或你的决定给出。
- 语义带指纹：对象体积涨跌 ≥25% 且 ≥1 MB（目录）或内容/日期变化（文件）后，旧语义会标「已变化」，
  提示你重新看；没变的直接复用，不再花模型调用。
- 不提供回收站 / 隔离区 / 撤销——因为它们属于执行面，v0 刻意没有执行面。
- 历史只保留顶层聚合；要看更早的变化需要在账本上限内重扫。
- 画布面积严格等于体积：小项会小到不足 1 像素（真实主目录里 76 项有 42 项如此），
  树图上点不到——列表视图里全都有。这不是 bug，是单层树图对「少量大项 + 长尾小项」的诚实表现。
- **跨层索引是按目录名匹配的**（node_modules / Caches / dist / build / target / __pycache__ / .venv / Logs / .Trash / DerivedData），
  不是全量文件索引：同名但实际用途不同的目录会进索引（所以 build/target 那组标的是「谨慎」），
  反过来名字不在规则里的目录不会被收进来。每组最多展示前 200 条，合计仍按全部算。
- 规则跟着**提案快照**走（齿轮菜单「导出提案」），不再单独导出规则文件；提案导入是合并，不覆盖已有的决定。
- 记忆规则按**目录名**生效，不是按路径：它会在每次扫描后给新出现的同类目录补一个决定（`by: rule`），
  所以规则开着的时候，扫描会顺带改写一批标注——这是「记住」的含义，撤销规则可以整体收回。
- 自动扫描依赖 dsh 进程活着；没有后台常驻，也没有系统级 launchd 定时器。
- 清理脚本只做「移动到废纸篓」，没有「恢复」按钮，也不维护隔离区——恢复去废纸篓自己找；
  插件也不会替你清空废纸篓。
- 执行台账靠「上一轮扫描 + 你的决定 + 这一轮扫描」推出来：别人手动删掉、被别的程序清掉的项，
  只要标过待清理，也会记成「已移走」——它记的是「不在了」，不是「谁删的」。
- 扫描预算：每个直接子项 200 万条目 / 40 秒，全局 90 秒。预算定得太小会让同一个目录每次扫出不同体积
  （结果取决于 readdir 顺序），这条踩过坑——被截断的项在检查器里用 `≥` 标出来。
- 缩放是几何 + 语义两层：方块和间距按倍率放大，文字/内边距反向缩回去，所以看起来字号不变；
  上限 6 倍，不做动画补间。
